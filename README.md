# MARKET PULSE 3.1 — 3.0 기능 유지 + KOSPI 지수 복원

> **CSV 파일 없이 앱을 열면 기본 6개 관심종목과 KOSPI 종합주가지수의 실제 온라인 일봉 조회가 자동으로 시작됩니다.** CSV는 선택적 자료 업로드·비교 기능입니다. 실시간 체결가가 아닌 공급처 제공 **과거 일별 가격(OHLCV)** 입니다. 온라인 서비스가 실패하면 임의의 가격이나 수익률을 생성하지 않습니다.

이 문서는 **실행 안내·기능 설명·배포 안내·검증 결과·주의 사항을 하나로 합친 유일한 설명 파일**입니다. 2.3의 여러 배포/검증 문서는 중복을 없애기 위해 패키지에서 제외했습니다.

## 3.1에서 복원한 KOSPI 시장 지수

- **홈 대시보드**의 기존 통계 카드 아래에 **KOSPI 종합주가지수** 카드, 전 거래일 대비 포인트·등락률, **1개월/3개월/6개월/1년/전체** 차트를 추가했습니다.
- **국내 시세 보드** 상단에도 KOSPI 최근 종가·등락률·기준일을 표시합니다. 기존 종목 검색, 추가·삭제, 차트·뉴스·AI 예측 등 모든 메뉴는 유지합니다.
- **CSV가 필요 없습니다.** 앱 시작 시 기본 6개 종목과 KOSPI 지수를 **서로 독립적인 API로 자동 조회**합니다. KOSPI가 실패해도 개별 종목 조회는 계속됩니다.
- 지수 데이터는 FinanceDataReader의 공식 `KS11` 일봉을 우선 사용합니다. 그 제공처의 마지막 기록이 7일 이상 오래됐거나 실패했다면 **Yahoo Finance `^KS11` 일봉 차트**를 보조로 시도하여 더 최근 실제 관측값이 있을 때만 교체합니다. 보조 제공처도 접속 제한·응답 실패가 발생할 수 있습니다.
- 최신 데이터가 없을 때 **임의의 지수 값을 만들어 표시하지 않습니다.** 실제 캐시가 있으면 해당 기록을 보여주되 저장 데이터임을 명시하며, 조회가 오래됐으면 마지막 거래일·경고를 표시합니다.
- KOSPI는 개별 주식이 아니므로 **원 단위가 아닌 지수 포인트(pt)**로 표기하며 6자리 관심종목·기업 검색·예측 대상에 섞지 않습니다.
- 백엔드에서 `GET /api/index/kospi?days=460`와 `GET /api/index/kospi/cached?days=460`을 지원합니다. 실제 관측된 지수 기록은 서버 `data_cache/KS11.csv`에 저장됩니다. 15분 메모리 캐시를 사용합니다.

**지수 값은 장중 체결가가 아닌 확인 가능한 마지막 거래일의 일별 종가**입니다. FDR 또는 Yahoo의 서비스 정책·갱신 지연에 따라 날짜가 최신이 아닐 수 있으므로 반드시 화면의 날짜와 출처를 확인하세요.

## 1. 가장 중요한 보존 사항

- 기존의 **남색 사이드바, 흰 카드, 민트색 강조, 로고·이미지, 8개 메뉴** 유지. `index.html`, `assets/`, 원본 Python 분석·뉴스·시세 엔진은 2.3과 내용이 동일합니다.
- 기본 6개 기업(삼성전자, SK하이닉스, 현대자동차, 기아, NAVER, 카카오)은 **앱 시작 시 주가 자동 조회**. 처음 8개 관심종목에 대한 조회가 자동으로 시작되며, 추가한 종목도 자동 조회합니다.
- 이름 검색, 6자리 코드 직접 입력, 관심종목 추가·삭제, KRX 검색, 15분 가격 캐시, 저장된 **실제** 종가 우선 표시 기능 보존.
- 원래의 뉴스 URL → GroqCloud 심층·일반 분석, AI 상승 방향 확률 추정, 시계열 검증, 급변 탐지, CSV 선택 업로드 유지.
- Google AI Studio·npm·Node.js는 **앱 실행에 필요 없음**. Node.js는 선택적인 프런트엔드 **개발 테스트 도구**로만 사용합니다.
- 기존 2.3의 로컬 Windows 실행과 Docker 클라우드 배포 방식 보존.

## 3. 개인 컴퓨터에서 실행하기 (Windows / VSCode)

1. ZIP을 새 폴더에 **압축 해제**합니다. 최상위에 `app_server.py`, `index.html`, `requirements.txt`, `src/`, `assets/`가 있어야 합니다.
2. VSCode에서 해당 폴더를 열고, 터미널에서 다음 명령어를 실행합니다.

```powershell
python -m pip install -r requirements.txt
python app_server.py
```

3. Chrome에서 **http://127.0.0.1:8765**를 엽니다. 또는 `실행하기_윈도우.bat`를 더블클릭합니다.
4. **어떤 CSV도 업로드하지 않은 채** 홈 화면을 확인하세요. 기본 6개 종목의 온라인 조회가 자동으로 시작됩니다. 첫 조회는 인터넷 연결과 NAVER/KRX 데이터 제공처 응답이 필요합니다.
5. 왼쪽 사이드바에서 기업명·6자리 종목코드를 검색해 종목을 추가하면 자동 조회됩니다. 관심목록은 브라우저별로 저장됩니다.

macOS/Linux:

```bash
python3 -m pip install -r requirements.txt
python3 app_server.py
```

`run_mac_linux.sh`도 사용할 수 있습니다.

### 주가가 바로 나오지 않을 때

- 홈의 조회 상태와 종목별 오류를 확인하고, **관심종목 가격 새로고침**을 사용하세요.
- `finance-datareader` 라이브러리가 설치되어 있는지, 네트워크 및 금융 데이터 제공처에 접속 가능한지 확인하세요.
- 이미 저장된 **실제 가격**이 있을 때만 캐시를 먼저 표시합니다. 새 폴더에서 오프라인으로 실행하면 처음부터 값을 표시할 수 없습니다.
- 실시간 체결가를 제공한다는 뜻이 아닙니다. 최신성은 **마지막 거래일·원출처·저장 데이터 여부**로 확인하세요.

## 4. GroqCloud 뉴스 분석 (선택)

**주가 조회에는 GroqCloud API 키가 필요하지 않습니다.** 공개 뉴스 URL을 AI로 분석할 때만 키를 사용합니다.

- 프로젝트의 `.env.example`을 복사해 `.env`라는 이름으로 저장합니다.
- `.env`에서 `GROQ_API_KEY=` 뒤에 본인 키를 입력합니다. `GROQ_MODEL=openai/gpt-oss-120b` 모델은 제공처에서 지원되는지 계정 설정을 확인할 수 있습니다.
- 기존과 동일하게 일반 분석은 AI 요청 1회, 심층 분석은 근거 재점검을 포함해 통상 2회 요청합니다.
- `GROQ_DAILY_REQUEST_CAP=24`는 **앱 내 자체 상한**이며 공급사의 요금·과금·실제 쿼터를 보증하지 않습니다.
- API 키는 **`.env`, GitHub 비밀정보, 클라우드 환경변수**에만 저장합니다. 공개 저장소, 스크린샷, 채팅, 브라우저 JavaScript에 넣지 마세요.

## 5. GitHub 및 무료 컨테이너 배포

1. **프로젝트 파일을 GitHub 저장소 최상위**에 업로드합니다. ZIP 하나만 업로드하거나 `.env`를 올리면 안 됩니다.
2. Python Docker 컨테이너를 지원하는 호스팅 서비스에서 GitHub 저장소와 `Dockerfile`을 연결합니다.
3. 서비스 설정의 **Container Port = `8765`** (또는 서비스의 동적 `PORT` 설정)을 확인합니다. Dockerfile은 `app_server.py`를 실행합니다.
4. 환경변수 설정에서 필요시 `MARKET_PULSE_SITE_PASSWORD`를 지정하고, 뉴스 분석이 필요하면 `GROQ_API_KEY`를 비밀 변수로 등록합니다. **환경변수를 GitHub 코드에 작성하지 마세요.**
5. 배포가 성공하면 호스팅 업체가 제공하는 HTTPS 주소로 접속합니다. 앱은 사용자가 Windows에서 Python을 실행하지 않아도 동작합니다.

무료 호스팅은 **메모리·실행 시간·휴면 정책·결제수단 인증**이 바뀔 수 있습니다. 특정 서비스에서 무조건 카드 없이 영구 무료 운영을 보장하지는 않습니다. 무료 컨테이너는 수백 MB 메모리 한계 때문에 `scikit-learn` 모델의 실시간 학습 요청이 느리거나 중단될 수 있습니다.

### 공개 사이트 운영 주의

- 사이트 비밀번호는 API 자원 보호에 도움이 됩니다. **공개 앱**이라면 각 사용자에 대한 로그인과 서버 측 요청량 제한, 자원 보호가 추가로 필요합니다.
- 주가 캐시를 서버 디스크에 저장하므로 **재시작 시 저장공간이 초기화되는 무료 서버**에서는 이후 접속 시 재수집할 수 있습니다.
- `MARKET_PULSE_DATA_DIR` 환경변수로 영구 디스크 경로를 지정할 수 있지만 **실제 저장소 제공 여부는 호스팅 계정 조건**에 따릅니다.
- 기사 본문과 재무 데이터의 이용 약관·저작권·공개 재배포 허용 범위도 확인해야 합니다.

## 7. 실제 검증 범위와 한계

실행 검증을 위해 다음 명령을 사용했습니다.

```bash
python -m unittest discover -s tests -v
node --test tests/test_v3_analytics.mjs
node tests/frontend_smoke.mjs
node tests/frontend_kospi.mjs
```

- **Python 59개**, **3.0 분석 JavaScript 10개**, 기존 프런트엔드 상태 검사 **9개**와 KOSPI 화면 상태 검사 **8개** 통과. 기존 Python·이미지·HTML 파일을 2.3 원본 해시와 비교하는 회귀 테스트 포함.
- **브라우저 기능 시나리오 통과:** CSV 없이 기본 6개 종목 자동 조회, 신규 종목 추가 시 자동 조회, 두 종목 공통 날짜 비교, 차트 기간 전환, 메모 저장, CSV 내보내기, JSON 설정 백업·복원, 관심종목 삭제, 8개 메뉴 전환, 모바일 입력창.
- 브라우저 기능 시나리오는 **테스트에서만 주가 API를 모의 응답으로 대체**했습니다. 모의 가격은 실제 배포용 코드·배포 ZIP에 포함되지 않습니다.
- Python HTTP 서버는 서브프로세스로 실행해 정상 응답을 확인했습니다. **실제 외부 주가 공급처·GroqCloud 계정·무료 호스팅 클라우드 배포 연결은 이 환경에서 성공을 검증하지 못했습니다.** 실제로 인터넷이 연결된 사용자 환경에서 마지막 거래일과 오류 상태를 확인해야 합니다.
- 시장 분석 정보는 교육·연구 목적의 참고 자료입니다. 예측값은 검증된 미래 수익을 의미하지 않으며 투자 권유가 아닙니다.

## 8. 2.3/3.0에서 업데이트하는 방법

**기존 GitHub 파일을 바로 덮어쓰기 전에 백업**하고, 가급적 새 폴더에 이 ZIP을 풀어 실행하세요. 3.0에서 실질적으로 수정한 애플리케이션 파일은 `src/app.js`, `src/analytics.js`입니다. 회귀 테스트와 통합 설명서도 갱신했습니다. Python 시세·뉴스·예측 코드와 주요 화면·이미지는 2.3 원본 그대로입니다. 로컬 `.env` 및 개인 실제 주가 캐시는 ZIP에 포함되지 않으며, 기존 사용자는 별도로 보관해야 합니다.

## 9. 3.0에서 3.1로 변경되는 정확한 소스 파일

- `market_api.py`: KOSPI 실제 일봉 조회, 최신성 경고, 보조 제공처·캐시·전 거래일 대비 계산을 추가
- `app_server.py`: KOSPI 전용 읽기 API 경로와 독립 조회 동시성 제한 추가
- `src/app.js`: 홈 지수 카드/차트, 시세보드 지수표, 자동 로딩·새로고침·기간 선택 추가
- `styles.css`: **원래 스타일 뒤에 KOSPI 화면 스타일만 추가**, 기존 시각 규칙은 유지
- `tests/test_kospi_index.py`, `tests/frontend_kospi.mjs`: 실제 인터넷이 없는 환경에서 KOSPI 지수 경로와 UI를 검증하는 회귀 테스트 추가
- `tests/test_cloud_deployment.py`: **의도적으로 수정한** `market_api.py`/`app_server.py` 두 파일은 고정 해시 비교 대상에서 제외하고, 그 외 기존 핵심 파일의 원본 해시 검증 유지
- `README.md`: 기존의 **유일한 사용 설명서**에 3.1 변경사항 통합. 별도의 설명 문서를 늘리지 않음

실제 외부 금융 API가 성공했다고 보증하지 않습니다. 자동 테스트의 지수 수치는 테스트 전용으로만 사용하며 배포 코드·기본 캐시에는 포함되지 않습니다.
